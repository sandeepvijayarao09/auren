# Round 9: Auren Router

> ⌚ *"I'm running 15 late. Tell office hours, push my 3 PM, and draft a reply to Prof. Lee."*
> → `{"apps":["slack","calendar","gmail"],"risk_tier":"send","reply_surface":"watch","needs_vision":false}` → *"On it: Slack, calendar and Gmail."*

Core now routes every command at the fast lane, before Wonder's first turn. The route is **advisory**: it preloads the namespaces it names, starts the camera early for a "this" command, and shapes the spoken ack. It never touches the tier gate. Routing goes Glimmer LoRA (when `AUREN_ROUTER_URL` is set, 300 ms budget), then Muse Spark (when a key is set), then deterministic rules. On the Python side, everything needed to build the data, train the LoRA, serve it and score it against Wonder and Spark is written and tested. It just hasn't run, because there are no Modal credits or API key yet.

## What was built
### Python (`router/`)
| File | What it does |
|---|---|
| `auren_router/system_prompt.txt`, `prompt.py` | **The one prompt.** The rubric condensed into a system prompt, plus `render_user(text, context)`. Devices are sorted by kind, with inputs and outputs in protocol order, so one situation always renders the same way. Data, training, serving, evaluation and Core all use it; Core reads the same `.txt`. Also `parse_context`, `training_row` (prompt/completion, so the loss falls on the answer only) and `strip_fences`. |
| `seed/seed.jsonl` | **129 hand-written labelled examples.** Every app 13–44 times, read 54 / write 35 / send 40, every reply surface 27–38 times, 22 vision. There are 15+ device situations, including a screen-only web surface and a command typed into the API with no surface. They include the rubric's own examples, and each line passes `parse()`. The seed is always held out. |
| `auren_router/data.py` | `seed` checks and copies the seed. `logged --file/--url` reads Core's export (`--url` must point at this Mac). `synthetic` makes an even grid of (apps × tier × device situation) cells and asks `muse-spark-1.3-contributor` for 10 commands per cell; `muse-wonder-1.0` labels each with `rubric.md` word for word through the OpenAI SDK at `api.meta.ai/v1` (Responses API). Anything `parse()` rejects is dropped. It dedupes, runs in waves, stops at `--n`, and appends, so a stopped run can resume. `build` dedupes per (command, situation) and splits 85/5/10 by a hash of the normalised command; the seed and anything that repeats a seed command always go to test. It also writes `handcheck.jsonl` (100 train rows to read by hand). |
| `auren_router/train.py` | A Modal app: QLoRA (4-bit nf4, r 16, α 32, all-linear) with TRL's `SFTTrainer` on one H100, 1–2 epochs. Rows are chat-formatted on the Mac with `prompt.py`. **Required:** `--base` / `AUREN_ROUTER_BASE`, with no default, and `--i-checked-the-terms` (the Meta terms TODO). It writes the adapter and `meta.json` (base, prompt sha256, counts, settings) to the `auren-router` volume. |
| `auren_router/serve.py` | A Modal app: `vllm serve <base> --enable-lora --lora-modules auren-router=…` behind `@modal.web_server`, `min_containers=1` (kept warm), `@modal.concurrent(32)`, on an L40S by default (`AUREN_ROUTER_GPU`). The API key comes from the `auren-router` secret as `VLLM_API_KEY`, never argv. A deploy without `AUREN_ROUTER_BASE` stops. |
| `auren_router/evaluate.py` | Any number of OpenAI-compatible endpoints (`chat` or `responses`) on a test JSONL, all with Core's prompt. It reports valid %, per-field accuracy, exact match, missed sends, p50/p95 and cost per 1K. Costs come only from flags: `--price` (per 1M tokens) or `--hourly` (per GPU hour, spread over the measured latency and `--concurrency`). Standard library only; `--fake` and injectable clients make it testable. |
| `tests/parity.json` | Accept/reject cases that both `parse()` and Core's zod `Route` are held to. |
| `README.md` | Rewritten: how Core routes, the data, train, serve and evaluate commands. |

`modal`, `openai`, `torch`, `vllm` and the rest are imported lazily, so the 34 tests need nothing installed. `pyproject.toml` and `uv.lock` are unchanged: use `uv run --with modal` and `uv run --with openai`.

### Core (`core/src/router/`)
| File | What it does |
|---|---|
| `prompt.ts` | Reads `router/auren_router/system_prompt.txt`. `renderUser` and `routerMessages` mirror `prompt.py` line for line. Zod `RouteContext` / `RouteDevice`. |
| `router.ts` | **`Route`**: a zod strict object mirroring `schema.py` (same fields, enums and order, an extra field rejected, apps deduped in order). **`createRouter(deps).route(text, context)`** runs three sources in order: (a) Glimmer, a POST to `AUREN_ROUTER_URL` `/chat/completions` with an optional bearer key, aborted at the 300 ms budget (a racing deadline also covers endpoints that ignore the abort); (b) Muse Spark through Core's ledger-wrapped client, only with a key, 1 s budget; (c) **`rulesRoute`**. Output must pass `Route`, and anything off-schema, slow or failed falls through. Each Glimmer call writes an `Auren Router` ledger row with the host, size and timing; Spark's row comes from `ledgerMuse`. Each attempt logs one `router.route` line (source, ms, ok, reason, plus the route's app names on success), never the text. `holdMs` is how long Wonder may wait: the budget with Glimmer, 0 without. |
| | **The rules** read clause by clause. Keywords map to apps, kept only if that namespace is registered. An undo clause means receipts and nothing else; "what did I…" means memory. "This", "these", "that poster" or "here", with a camera online, add glasses first and `needs_vision`; time words ("this morning") and "that's" don't count, and "near here" isn't vision. Send words (post, tell, invite, book, reserve, email…) set the tier, which only shapes the ack; question clauses are reads. The reply surface follows the rubric's presence rules. |
| | **`startHints`** is the one entry point the loop uses. It routes, prefetches a frame when the route needs vision and a camera is online (unless Wonder's first turn is already back), resolves the ack text, and races the route against `holdMs` to decide the preload. **`ackFor`** gives "On it: Slack, calendar and Gmail.", "Checking calendar." or "Looking now, then calendar.". |
| `examples.ts` | **Free labels.** It walks the event log: each utterance (which now carries the devices online) through its reply becomes `{text, context, label, source: "logged", at, event_id}`. The label is the namespaces of the `tool_call`s in call order, the highest tier among them (a declined send still counts), the kind of the surface `reply.spoken_on` named, and whether `glasses.look` ran. Overlapping commands (a second utterance before the first reply), failed commands, utterances without device context and replies to unnamed surfaces are dropped. It pages through `since()`. |

### Shared files (small, each marked `R9`)
- `core/src/agent/loop.ts` (+29 / −10 lines):
  - `AgentDeps.router` and `AgentDeps.prefetchFrame`.
  - The utterance event gains `devices` (id, kind, inputs, outputs, active).
  - The fast lane calls `startHints`; the first turn awaits `hints.preload` (at most `holdMs`), and `toResponsesTools(ctx, preload)` runs every turn of that command, so preloaded tools stay loaded.
  - `fastAck` takes the route's ack and asks Spark only when the route names no apps.
  - **`executeCall` and the tier gate are untouched.**
- `core/src/tools/registry.ts`: `toResponsesTools(ctx, { preload })` un-defers the named namespaces' tools (and drops `tool_search` when nothing is left deferred). It can't add an unavailable namespace or hide one. Also adds `names()`.
- `core/src/vision/capture.ts`: `CaptureBroker.prefetch(purpose)` and `PREFETCH_TTL_MS = 3000`. `request()` takes the early frame if one is in flight. After 3 s it's dropped, and its pending entry is removed, so a late frame gets `unknown`. No prefetch happens without a camera or while a capture is already waiting. The old `request()` body moved, unchanged, into `#capture`.
- `core/src/surfaces.ts`: `isActive(id)` (five lines after `online()`).
- `core/src/server.ts`: `GET /v1/router/examples`, served as `application/x-ndjson`, `no-store`, and only from this Mac (`fromThisMac`, as for `/v1/pair/start`).
- `core/src/config.ts`: `routerUrl`, `routerKey`, `routerModel` (default `auren-router`), `routerBudgetMs` (default 300), in a block after `memoryModel`.
- `core/src/index.ts`: builds the router, passes `...r9` (router + `frames.prefetch`) into the deps, and prints a `router:` line at boot.
- `.env.example`: `AUREN_ROUTER_URL`, `AUREN_ROUTER_KEY`, `AUREN_ROUTER_MODEL`, `AUREN_ROUTER_BUDGET_MS`.

## How to run it
```bash
make dev    # boot prints "router: rules" (no key), or "Muse Spark, then rules" with MODEL_API_KEY
curl -s http://127.0.0.1:8787/v1/router/examples | head    # free labels from the commands you've run
cd router && uv run python -m unittest discover -s tests -t .
uv run python -m auren_router.data seed && uv run python -m auren_router.data build
uv run python -m auren_router.evaluate seed/seed.jsonl --fake
```
The ops log shows `router.route` (source, ms, ok) per command and `router.prefetch` when the camera started early. Train and serve commands are in [router/README.md](../../router/README.md).

## What isn't verified
- **No trained model.** Nothing has been trained, served or evaluated live. `train.py` and `serve.py` have never run on Modal, and the TRL, PEFT and vLLM argument names are from their current docs, not from a run. Pin the versions that work on the first run.
- **Muse Glimmer's model id and Hugging Face repo are unknown.** The base is a required setting with no default. Whether Glimmer is on Hugging Face at all, whether it's gated, and whether vLLM and bitsandbytes support its architecture are all open.
- **The Meta model API terms** on training with model outputs are still to check; `train.py` refuses to start until you say you have.
- **No live calls.** With no key, nothing has called Spark as a router, the generator `muse-spark-1.3-contributor`, or Wonder as labeller. The 1 s Spark budget is a guess; if Spark is slower, every route falls to the rules, which is safe but makes the Spark source useless.
- **No latency numbers.** The 300 ms budget is untested against a real Modal endpoint, and so is the "kept warm" claim. Cost per 1K needs real prices.
- **No accuracy numbers** for any model. The seed figure above is the rules only.
- Not tried on a device: the early capture on real glasses or a phone, and the shaped ack spoken aloud.

## Known limits
- **Preload holds Wonder only for Glimmer.** With Spark only (today's setup), `holdMs` is 0, so Spark's answer shapes the ack and may start the camera, but never preloads. With no key, the rules answer instantly and do preload.
- `reply_surface` is computed, logged and evaluated, but Core doesn't use it; the device picker still decides. Wiring it in is a follow-up.
- An early frame is only used if `glasses.look` runs within 3 s of the route, and Wonder's first turn has to fit in that window. If it doesn't, the frame is dropped and look asks again, so the camera runs twice for that command.
- The rules are English keyword rules, tuned on the seed. They misread phrasing they haven't seen ("Add Priya to the session" is a write to them, a send to the rubric).
- The export assumes one command at a time. Overlapping commands are dropped, not split. Commands from before R9 have no `devices` on their utterance and are skipped.
- `data.py synthetic` asks for 10 commands per call, with 2× headroom on calls; the yield after dedupe and validation is unmeasured.
