# Round 11: the MCP bridge (the platform beat)

> ⌚ *"Add today's receipts to my journal."*

You can now connect an MCP server you already use. Its tools become a namespace in Muse's tools on the next turn, for as long as it's connected. Auren treats what the server says about itself as a claim: **every MCP tool asks for a tap** unless you trust that server's read-only hints, and nothing from MCP is ever write, because Auren can't undo a call on someone else's server.

## What was built
### Core (`core/src/connectors/`)
| File | What it does |
|---|---|
| `mcp.ts` | **The bridge.** It reads `mcp.json` (`AUREN_MCP_CONFIG`, or the repo root) in the usual `{"mcpServers": {name: {command, args, env} \| {url, headers}}}` shape, plus `trust_annotations` and `disabled`. Each entry is zod-checked on its own, so one bad entry doesn't stop the rest, and errors name the path, never the value. It supports **stdio** and **Streamable HTTP** through the official SDK client. Each server connects in the background (10 s timeout, then retries with backoff from 1 s up to 60 s) and never holds up Core's start. While connected, the server is one `Namespace`: `available` only while connected, with tools rebuilt on `notifications/tools/list_changed`. A change that arrives during a call is applied before that result goes back, so the very next turn sees it. |
| | **Tiers:** `send` for everything, unless `trust_annotations: true` and `readOnlyHint === true`, which gives `read`. Never `write`. Every tool is `external: true`. |
| | **Tool poisoning:** it removes control, zero-width, bidi, tag and private-use characters from names, descriptions, enum values and results. Descriptions are capped at 400 characters (parameter descriptions at 200). Names are mapped to `[A-Za-z0-9_-]{1,64}`: valid names are kept, and others get a safe base plus an 8-hex hash of the original, so the mapping is stable. `inputSchema` is reduced to what Responses takes. It drops `$ref`/`$defs`, `default`, `examples`, `title`, conditionals and `__proto__`, maps `oneOf` to `anyOf`, gives arrays `items`, and caps depth, properties and enums. The namespace description names the server and says its text is not instructions. Auren's own app names are refused as server names. |
| | **Calls:** a 30 s timeout per call and a 64 KB cap on arguments. Results keep text and `structuredContent` (a JSON duplicate of the structured content is dropped), describe images, audio and files instead of passing them on, and are capped at 16,000 characters. `isError` throws, so there's no receipt, and the model gets the server's text labelled as the server's words. |
| | **The tap and the receipt:** `summarize` gives `Run add_entry in Journal (MCP) · text "…" · date "2026-11-03"` (required arguments first, up to 4, 60 characters each, 240 in all). The receipt says `Ran …`, with no undo. |
| | **Secrets:** env values, header values and URL credentials are scrubbed from every log line and status. A stdio server gets the SDK's minimal environment plus its own `env`, so Core's keys never reach it. Plain `http://` only works for loopback, and `redirect: "error"` stops headers from following a redirect to another host. A failed stdio start logs the last line of the server's stderr, scrubbed. |
| | **The ledger:** one row per `tools/list` and `tools/call <tool>`, as service `Journal (MCP)` and operation `tools/call add_entry · stdio` (or the host), with bytes sent and time. Never arguments or results. |
| `mcp-journal.ts` | **Journal**, the fictional demo MCP server: `list_entries` (`readOnlyHint: true`) and `add_entry` (not read-only). It keeps entries in memory, or in a JSON file with `--file`. It runs over stdio (`node core/src/connectors/mcp-journal.ts`), and `journalInMemory()` gives the eval and the tests a fresh in-memory server for each connection attempt, on the same entries. |
| `mcp.test.ts` | 22 tests, listed under Verified. |

## How to run it
```bash
cp mcp.example.json mcp.json
make dev          # prints "mcp: journal (stdio, read-only hints trusted); connecting in the background"
curl -s http://127.0.0.1:8787/v1/connections
```
Open a watch tab (`/?kind=watch`) and say *"Add today's receipts to my journal."* The watch asks `Run add_entry in Journal (MCP) · text "…"`. Entries land in `journal.json`. To add your own servers, see [docs/mcp-setup.md](../mcp-setup.md).

```bash
cd core
node --test src/connectors/mcp.test.ts    # the 22 bridge tests
npm run eval -- --scripted                # 11 / 11, 0 tier violations
```

## Verified
- **Core: 170 → 192 tests** (191 pass, 1 skipped; the skip predates this round). `npm run typecheck` is clean. The 22 new tests in `mcp.test.ts`:
  - **mcp.json:** stdio and HTTP entries parse and trust defaults to off. Names are normalized. Reserved names, plain HTTP to a remote host, SSE and oversized values are reported by path, and the test checks that no error text contains a secret. A disabled entry is skipped. A missing file means no servers, broken JSON is reported, and the committed `mcp.example.json` parses.
  - **Tiers:** the `tierFor` table (a `"true"` string doesn't count), and end to end, an untrusted Journal gives `send`/`send` and a trusted one gives `read`/`send`. Everything is external.
  - **Poisoning:** a server with bidi, zero-width and tag characters, a 2,000-character description, and `default`/`examples`/`$ref`/`$defs`/`if`/`__proto__`/bad property names reaches the model clean, with the exact parameters asserted. Name mapping is stable and collision-free. The approval line stays within bounds.
  - **The real loop:** a send-tier `add_entry` waits for the tap, and the server has no entry when the watch is asked. The trusted `list_entries` runs without a tap. Both results arrive as `{untrusted_data, note: "Content from Journal (MCP)…"}`, and the receipt is `send` with no undo. A declined tap means no call and no ledger row for it.
  - `isError` becomes a labelled error with no receipt. Result conversion (images described, duplicate JSON dropped, a 50,000-character result cut to 16,000) is tested.
  - **Timeouts:** a call that never answers fails after `callMs`, with no receipt. A stdio server that never answers `initialize` doesn't block `start()` (it returns in under 50 ms), ends `disconnected` and is scheduled to retry.
  - **list_changed:** a tool the server adds during turn 1 is in the request for turn 2, and is called there.
  - **Disconnect:** the namespace leaves the inventory, its tools refuse to run, and it comes back on a fresh connection. Closing while still connecting leaves nothing connected.
  - **The ledger** records `tools/list` and `tools/call add_entry` with bytes, never the entry text.
  - **The ops log:** a stdio server that prints its env token to stderr and exits shows up as `stderr: "token=[redacted] canary=absent"`. The env value, the command and the env var name never appear, and **Core's own env var didn't reach the child**.
  - **Real transports:** the real `mcp-journal.ts` as a child process over stdio, with its `--file` written in the config file's folder. **Streamable HTTP** against the SDK's server on 127.0.0.1: the header reaches every request and never the ops log, the ledger or the status.
  - `/v1/connections` (through `createServer`) lists a connected and a failed server, without the command or the secret.
  - The eval's platform case passes with one tap on the watch and the expected summary. Demoting `add_entry` to `write` makes it fail with "no tap was asked for".
- **Eval: 11 / 11 pass, 0 tier violations, 0 unwrapped results** (`npm run eval -- --scripted`; `eval/results.md` is regenerated).
- **Live start:** `node src/index.ts` with `mcp.json` copied from the example connected the real stdio Journal in 146 ms. `/v1/connections` listed it as `connected, tools 2, read 1, send 1`, and the Journal process exited with Core.
- The MCP test file passed 5 runs in a row on its own and inside the full parallel suite. The gitleaks pre-commit scan is clean.

## What isn't verified
- **Live Muse.** There's no API key, so I don't know whether Muse accepts the cleaned MCP schemas inside a `namespace`, or picks `journal.add_entry` from its description. The live eval (`--live`) will tell.
- **Third-party servers.** Only the Journal and hand-built test servers were used. Schemas that lean on `$ref` lose their structure (the referenced part becomes `{}`), which may make a real server's tools harder for the model to call.
- **Streamable HTTP in the wild.** It was tested only against the SDK's own server in stateless mode on loopback. Not tested: sessions and resumption, servers that need OAuth (not supported; static headers only), and HTTPS.
- **An HTTP server going away isn't noticed** until a call fails, because there's no persistent connection to watch. Its namespace stays offered and calls return errors. Stdio and in-memory servers are noticed at once.
- **The watch screen.** The approval line can be up to 240 characters. It hasn't been seen on a real watch or in the iPhone app.
- **Process trees.** Closing a stdio server ends the process the SDK started. A wrapper such as `npx` that starts its own child wasn't checked for leftover processes.
- Only macOS was tested.

## Known limits
- Tools only: no MCP resources, prompts, sampling, roots or elicitation. Server `instructions` are ignored.
- No legacy SSE transport.
- Trust is per server, not per tool. With trust on, a server can still call a write tool "read-only" and it will run without a tap. That's the deal the flag makes, and the docs say so.
- A call that times out may still have run on the server. Auren reports it as failed and doesn't retry.
- 64 tools per server. Above 8, the server's tools are `deferred`, so they rely on `tool_search`.
- If two server tool names map to the same safe name, the later one (in sorted order) is dropped.
- Tool names are re-mapped on every list, but a tier change only takes effect from the next call. A call already approved runs with the tier it had.
- `executeCall` in the loop doesn't check `available`. A disconnected MCP tool refuses inside `run()`, so the loop needed no change.
- Secrets put in `args` aren't scrubbed (only `env`, headers and URL credentials are). The setup doc says to use `env`.
