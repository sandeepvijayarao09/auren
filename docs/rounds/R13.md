# Round 13: the judges' sandbox, token usage and a spend limit

> 🌐 *Open `/try`, tap "Running 15 late", then tap **Post** on the simulated watch.*

Judges can't connect their own Slack and Gmail, and the model credits haven't arrived. So Core can now run as a **public sandbox**: `/try`, on a fictional demo world, with a simulated iPhone, Apple Watch and glasses, safe for strangers and working with or without a key. Separately, **every model call now counts its tokens**, and two settings set a spend alarm and a spend limit.

## What's built
### Token usage and spend limits (for every Core, not just the sandbox)
| File | What it does |
|---|---|
| `core/src/security/ledger.ts` | The outbound ledger gains `model`, `tokens_in` and `tokens_out` columns, added to an existing table by an **additive migration**. `ledgerMuse` reads `usage` from every Responses call (zod-checked, with the chat-completions names as a fallback) and records it, so **the agent loop, the fast ack, vision (Spark and SAM) and computer use** are counted in one place. One `usage` line per call goes to the ops log. New: `totals()` (kept in memory), `usage()` (per service and model), `onUsage()`. |
| `core/src/memory/spark.ts` | Auren Memory's Spark Open calls (Baseten, chat completions) record their tokens in the same ledger. |
| `core/src/obs/spend.ts` | `SpendGuard`, in tokens (Muse prices aren't published, so no money is invented). **`AUREN_TOKEN_ALARM`**: once the total passes it, one `usage` event and one ops warning. **`AUREN_TOKEN_LIMIT`**: once it's reached, `refusal()` returns a clear message. A total already past a line at start-up isn't announced again. |
| `core/src/server.ts` | At the limit, `start()` logs the utterance and the refusal instead of running (WebSocket, HTTP and voice), and `/v1/command` answers **429** with the message. Approvals already waiting are untouched, so they still resolve. `/v1/trust` gains `usage` (totals, per model, alarm, limit, alarmed, limited). |
| `apps/web/index.html` | A banner for the alarm and the limit, from the `usage` event as it happens and from `/v1/trust` on load. |

### The sandbox (`AUREN_SANDBOX=true`, `make sandbox`)
| File | What it does |
|---|---|
| `core/src/index.ts` | A guard before anything else runs: in sandbox mode it awaits `runSandbox()` and exits, so **the master key, `auren.db`, connectors, devices, the camera and the driver are never created**, whatever `.env` says. |
| `core/src/sandbox/main.ts` | Builds the sandbox from config, with an **in-memory** ledger. Binds to `HOST` or 127.0.0.1 (`AUREN_TOKEN` doesn't open it). Prints the settings it ignores. |
| `core/src/sandbox/server.ts` | Serves `/try`, `/try/api/{session,state,command,taps/:id,receipts/:id/undo}`, `/health` and `/brand/{tokens.css,mark.svg}`. **Every other route on every method is a 404**, and every WebSocket upgrade is dropped. The page gets a strict CSP with a per-response script nonce. Bodies are capped at 4 KB, and inputs are parsed with zod. |
| `core/src/sandbox/sandbox.ts` | Visitors, limits, expiry and the two engines (below). |
| `core/src/sandbox/visitor.ts` | One visitor: a 128-bit random id, their own `evalWorld` (demo Calendar, Slack and Gmail, the eval's camera and demo booking site, Memory and receipts), their own in-memory `EventLog` and `SurfaceRegistry`, and a simulated phone, watch and glasses kept present by a shared ticker. A capture request is answered with the eval's synthetic poster. |
| `core/src/sandbox/limits.ts` | `clientIp()`: `X-Forwarded-For` only with `AUREN_TRUST_PROXY`, and then only the entry the trusted proxies added. `rateKey()`: IPv4, or an IPv6 /64. `Limiter`: a sliding minute and a UTC-day count per key. |
| `core/src/sandbox/catalog.ts` | The one-tap examples, read straight from `eval/cases` and `eval/scripts`: GP1, GP2, GP3 (the watch comes off), GP4, GP5 recap, GP5 undo, and the planted email. |
| `apps/web/try.html` | The page (its own file, so it doesn't collide with the console). Side by side, stacked on a phone: the iPhone timeline with receipts and Undo; the simulated watch with the tap (gold wash, the button names the action: Post, Send, Hold); the examples as chips; a free-text box; the engine badge; and **"What Auren just did"** (each tool with its tier, the tap and where it went, receipts, the reply). On brand tokens, dark, 16 px gutters, no horizontal scroll at 375 px. |

**Engines.**
- **Live**, with `MODEL_API_KEY`: Muse Wonder plans on the visitor's demo world until `AUREN_SANDBOX_TOKEN_BUDGET` tokens are spent (across all visitors).
- **Replay**, without a key, once the budget is spent, at `AUREN_TOKEN_LIMIT`, or for five minutes after two live failures in a row: the example plays from `eval/scripts` **through the real loop** with the eval's `ScriptedMuse`. Core is real: the tier gate, the tap, receipts and Undo.
- Free text that isn't an example, with no live engine: "The live model isn't connected here, so this sandbox replays the golden paths. Try one of these," with the examples as chips.
- **Vision and computer use are always replayed** (the synthetic poster, the demo booking page), and the page labels those steps "replayed".
- The badge says "Live · Muse Wonder" or "Replay".

**Honest replays.**
- When a script expects a tap and the visitor declines, the scripted "Done: Slack posted…" is replaced with "Nothing went out without your tap…".
- GP5 asks for GP1 first. Undo refuses when there's nothing left to undo.
- A case's timed script plays too: GP3 takes the watch off at 3 s, so the tap moves to the phone. The watch comes back afterwards.

**Limits.**
- Per address: `AUREN_SANDBOX_RPM` (6/min) and `AUREN_SANDBOX_DAILY` (60/day) commands, 600 requests/min, and 3 sessions (a fourth replaces the oldest idle one).
- Overall: `AUREN_SANDBOX_MAX_VISITORS` (50) visitors and 12 commands at once.
- 280 characters per command, and one command at a time per visitor.
- A visitor's world expires after 30 min without a command, tap or undo (polling doesn't count), and after 4 h in any case.

### Shared pieces
- **`core/src/eval/scripted.ts`** (new): `ScriptedMuse`, `Turn`, `Script`, `loadScript` and `EVAL_DIR` moved out of `run.ts` unchanged, behind a small `ScriptHost` interface (`log`, `session`, `later`) that `Bench` already satisfies.
  - One addition: `{{output:key}}` reads `key` from the tool results that turn was handed, as a model would.
  - `eval/scripts/gp2-glasses-poster.json` now uses `{{output:event_id}}` for the invite instead of a hard-coded `evt_101`. That's the same id in a fresh eval world, and the right one in a sandbox world where GP1 ran first.
- `core/src/eval/world.ts`: `evalWorld()` also returns its `crops`, so the sandbox can show what the glasses "saw".
- `core/src/protocol.ts`: the `usage` event kind. `core/src/config.ts`: the R13 settings. `.env.example`, `Makefile` (`make sandbox`), `core/package.json` (`npm run sandbox`), `docs/runbook.md` (running and hosting the sandbox), `SECURITY.md` (spend limits, the sandbox, threat rows), `eval/README.md` (`{{output:…}}`).

## How to run it
```bash
make sandbox                       # http://127.0.0.1:8787/try (replay without a key)
AUREN_TRUST_PROXY=true PORT=8790 make sandbox && cloudflared tunnel --url http://127.0.0.1:8790   # for judges
AUREN_TOKEN_ALARM=500000 AUREN_TOKEN_LIMIT=1000000 make dev                                     # spend limits on the real Core
```

## What isn't verified
- **No live model.** There's no key, so the live engine has only run against a fake Muse. The `usage` field names (`input_tokens`, `output_tokens`) are OpenAI's; if Muse reports usage differently, change only `tokensOf()` in `ledger.ts`.
- **Not deployed.** No tunnel or host has been tried; the runbook steps are untested.
- **Not load-tested.** The limits are unit-tested, not measured under traffic. Nothing has been timed with 50 visitors polling.
- The page was checked in the Browser pane's Chromium only, not Safari or a real phone.

## Known limits
- The live budget and, in sandbox mode, `AUREN_TOKEN_LIMIT` count tokens **in memory**: a restart resets them. Core's own limits use the persistent ledger.
- A command that's already running can overshoot a budget or limit; only new commands are stopped.
- Without `AUREN_TRUST_PROXY` behind a tunnel, every visitor shares one address, so one set of limits and three sessions. Core logs `sandbox.proxy` once when it sees that.
- Replays follow the script: a free-text variation of an example doesn't replay. The demo booking page keeps the eval's `opentable.com` URL in its summary; nothing is fetched from it.
- Voice (Muse Voice Transcribe) reports audio, not tokens, so it isn't in the token totals.
- The sandbox page polls (0.4 s while a command runs, 1.5 s idle, 5 s hidden). There are no sockets.
