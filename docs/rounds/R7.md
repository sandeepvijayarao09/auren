# Round 7: computer use (GP4)

> 📱 *"Find a table for two near there at 8 and hold it."*

Auren can now use websites that have no API. The main agent calls one tool, `browser.run_task`. A nested Muse Wonder loop with the `{"type":"computer"}` tool then drives a real Chromium on the Mac through the driver. It browses on its own, and **the only tap comes at the commit**: when the next click would confirm, book or pay, the driver's commit guard stops, your phone or watch asks, and the driver clicks only after you approve.

## What was built
### Core (`core/src/computer/`)
| File | What it does |
|---|---|
| `actions.ts` | **The one module that knows Muse's computer-use shapes.** It mirrors OpenAI's schema: batched `actions[]` (and the older single `action`), `pending_safety_checks`, `computer_call_output` with a screenshot. It translates them into the driver's wire actions. It also maps keys to Playwright names (CTRL becomes ControlOrMeta, ⌘ on the Mac) and turns a newline in typed text into an Enter, so the guard sees it. |
| `runner.ts` | The nested loop. Each `computer_call` goes to the driver, and the screenshot goes back to the model. **Safety checks** become taps; only approved checks are acknowledged, and a decline ends the run. **A guard pause** becomes a send-tier tap, and only then does the driver get `commit`. **Limits:** 25 steps or 90 s of browsing; time spent waiting for your tap doesn't count. It writes a `browser_frame` event (a ~6 KB JPEG) per step, one `Web (browser)` row per step in the outbound ledger (host, action types, typed bytes; never contents), and `browser.*` lines in the ops log. |
| `hub.ts` | `/v1/driver`. One driver at a time (a newer one replaces the old with close code 4000) and one task at a time. Results are zod-checked, screenshots are capped at 12 MB and frames at 200 KB. Commands are correlated by `seq` and time out after 30 s. |
| `browser.ts` | The `browser` namespace. It appears in the model's tools only while a driver is connected, and its description lists the allowed sites. `run_task(task, url, summary)` is **`tier: "send"`, `commitPoint: true`, `external: true`**. |

### The commit point in the tier gate
A send-tier tool normally asks before it runs. Computer use can't do that: it has to browse first to reach the button. So `ToolSpec` gains `commitPoint`, and `executeCall` in `core/src/agent/loop.ts` (about 15 lines) changes like this:
- For a `commitPoint` send tool, Core skips the up-front tap and hands the tool `ctx.approveCommit(summary)`. That's a send-tier `requestApproval`, logged in the ops log as `tool.approval … at: "commit"`.
- **Core writes the receipt only if that tap approved.** A run that stops first (CAPTCHA, decline, step limit) leaves no receipt. A failed commit click makes `run_task` throw, so it leaves none either.
- The approval reads like `Hold a table for 2 at 8:00 PM · click "Complete reservation" on www.opentable.com`. The host comes from the driver's URL. The button text comes from the page, so it's quoted and cut to 60 characters.

### Driver (`driver/src/`)
| File | What it does |
|---|---|
| `executor.ts` | Playwright in Chromium, with a fresh context per task (no passwords, cards or cookies; downloads off; service workers blocked). It runs click, double_click, move, drag, scroll, type, keypress, wait and screenshot, plus back and forward. **Before every click, and before the end of a drag,** it reads the role and accessible name under the point from Chromium's accessibility tree (CDP), with a DOM fallback, and calls `checkClick`. **Enter and Space** check the focused control and its form's submit button. **Iframes:** it walks into the frame under the point, including cross-site frames that run in their own process, and a frame it can't read pauses rather than passes. **`commit`** re-reads the target and clicks only if it's still the same control. **The allowlist** covers every top-level navigation (redirects, links, popups); leaving it stops the run. **`seesCaptcha`** runs after every batch. |
| `frame.ts` | Shrinks the screenshot to a 400 px timeline frame in Node with `jpeg-js`. Chromium's scaled capture is avoided on purpose: in testing it left hit-testing in cross-site iframes out of step, so a later click went somewhere other than where the guard looked. |
| `client.ts` | Dials Core, says `hello` (viewport and allowlist), runs one command at a time in order, and reconnects with backoff. |
| `index.ts` | `npm start`: headed Chromium plus the client, configured from `.env`. |
| `protocol.ts` | Zod schemas for what Core sends, mirroring `core/src/computer/actions.ts`. |

### Elsewhere
- `core/src/server.ts`: the `/v1/driver` upgrade, accepted from this Mac (`isLocal`), or with `AUREN_TOKEN` when one is set. A tunnel without the token is refused.
- `core/src/index.ts`: creates the `DriverHub` and registers `browser`.
- `core/src/protocol.ts`: adds the `browser_frame` event kind.
- `apps/web/index.html`: the console shows frames on the timeline (only `data:image/jpeg;base64` sources are rendered).
- `core/src/eval/cases.test.ts`: `browser.run_task` is now a real tool in the case checks. A commit-point tool in a case that `stopped` (`gp4-captcha-stops`) needs no expected tap.
- `.github/workflows/ci.yml`: installs Playwright's Chromium in the driver job, so the executor tests run in CI.
- `.env.example`: `AUREN_DRIVER_ALLOW`, `AUREN_CORE_URL`. `driver/README.md` is rewritten.
- New driver dependencies: `playwright@1.64.1` (pinned to the Chromium 1248 in `~/Library/Caches/ms-playwright`), `ws`, `zod`, and `jpeg-js` (BSD-3, pure JS).

## How to run it
```bash
make dev                                       # Core on http://127.0.0.1:8787
cd driver && AUREN_DRIVER_ALLOW=opentable.com npm start
```
A Chromium window opens and Core's ops log prints `driver.online`. Now `browser` is in the model's tools. Send the GP4 command from the console with a phone tab open (`/?kind=phone`); frames appear on the timeline, and the Approve card shows up when the guard pauses.
- From another machine: set `AUREN_TOKEN` on both sides and `AUREN_CORE_URL=http://<mac>:8787` on the driver.
- `AUREN_DRIVER_HEADLESS=true` hides the window.

- **Live smoke run (not in the suite):** Core's real runner, hub and server against the real driver process (`node driver/src/index.ts`, headless) and Chromium, with a scripted Muse. Open the page, pick 8:00 PM, type a name, click "Complete reservation": it **paused**, one approval was asked, `commit` clicked it, and the run ended `committed` on the confirmation page in about 2 s. Frames were about 6 KB and screenshots about 16 KB.
- `make test` and `make typecheck` pass (Core 115, driver 20, router 5, AurenKit 20, keyd 6).

## What isn't verified
- **Live Muse computer use.** There's no API key, so nothing has called Muse with the computer tool. These are all taken from OpenAI's schema and the pre-event spike, and are unconfirmed for Muse: the tool shape (`{"type":"computer"}` with no parameters); `computer_call.actions[]`; the action field names; `pending_safety_checks`; `computer_call_output` with `computer_screenshot`; and whether `instructions` must be resent with `previous_response_id` (the runner resends them). If Muse differs, change only `core/src/computer/actions.ts` (and the `instructions` and `tools` fields in `runner.ts`).
- **The headed window.** The tests and the smoke run used headless Chromium. `npm start` is headed by default, through the same code path, but no headed run has been watched.
- **Real sites.** Nothing has run against OpenTable or Resy. Real booking sites may show a CAPTCHA or bot wall to automated Chromium; Auren stops there by design. For the demo, either allowlist a site that works or serve a demo restaurant page.
- **Speed.** Seconds per step against Muse is unknown; the spike's target was under 4 s.
- **The iPhone app** doesn't render `browser_frame` yet. The web console does.
- The eval case `gp4-captcha-stops` still names a fixture page "lands with the driver on Day 6". It isn't wired to the executor tests' CAPTCHA page, which is left for the eval runner (R10).

## Known limits
- The approval summary includes the button's text from the page, quoted and cut to 60 characters. The host beside it comes from the URL, not the page.
- Any process on the Mac can connect as the driver, the same trust Core already gives the console. Remote drivers need `AUREN_TOKEN`.
- The allowlist checks top-level navigations only. A page's own images, scripts and iframes load as usual (that's also how a CAPTCHA frame becomes visible).
- After an approved commit, the rest of that action batch is dropped, and the model continues from the new screenshot.
- If you close the Chromium window, the driver exits.
