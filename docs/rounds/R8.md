# Round 8: Auren Memory and voice undo

**GP5:** *"What did I get done today?"* then *"Undo the calendar move."*

## What's built
All of it is in `core/src/memory/`, plus small additions to four shared files.

| File | What it does |
|---|---|
| `memory/spark.ts` | `sparkOpen()`: Muse Spark Open (`meta-models/muse-spark-open-1026`) through Baseten's OpenAI-compatible chat completions. The client is injected (`ChatLike`). Every call is recorded in the outbound ledger as service **Baseten** (operation `chat.completions <model>`, bytes, ms, status) and in the ops log as `memory.call` (trace, tool, model, ms, token counts, ok). Contents never go to either. It times out after 8 s, removes any inline `<think>` reasoning, and throws on an empty or malformed answer so the caller can fall back. |
| `memory/history.ts` | Reads the session back out of the encrypted log: `sessionEvents` (pages through `since`, 500 at a time), `receiptsIn` (each receipt marked with the undo that reversed it), local days and times in the user's time zone, and the keyword matcher used by recall and undo. The matcher strips word endings, so "move", "moved" and "moving" all match, and adds everyday names for each app ("meeting" means calendar, "email" means Gmail). |
| `memory/memory.ts` | **`memory` namespace.** `recap(date?)` (read) recaps a day from receipts only, and also puts the receipt list on the best screen as a card. `recall(query)` (read) filters utterances, receipts and replies by keyword first, then asks Spark Open over only the matching entries, at most 20. |
| `memory/receipts.ts` | **`receipts` namespace.** `list_recent(limit?)` (read) returns the newest receipts first, with `can_undo` and `why_not`. `undo(receipt_id? \| description?)` (write) finds the receipt and runs it through the existing `undoReceipt`. With a description, it picks the most recent receipt that best matches it. With no keywords ("undo that"), it picks the most recent receipt. |
| `memory/memory.test.ts` | 15 tests (see below) |

**What goes to Spark Open.**
- A recap sends each receipt's local time, app name and summary, plus `sent` and `undone` flags. It never sends receipt ids, event, thread or draft ids, tool arguments, undo steps or links.
- A recall sends the question and only the matching entries.
- Every summary and every Auren reply is wrapped as `{"untrusted_data": …}`. Only the user's own utterances are left unwrapped. This covers more than email and chat, on purpose: summaries can quote event titles, and those are written by other people too.
- `recap`, `recall`, `list_recent` and `undo` all set `external: true`, so the agent loop also hands their results to Muse Wonder as untrusted data.

**Fallback.** If there's no `BASETEN_API_KEY`, or Spark Open errors, times out or returns an empty answer, the tool builds the answer locally. A recap becomes "3 things today. 3:02 PM · Moved "Office hours (CS 5800)" to 15:15 (undone). …", and a recall lists the five most recent matches. Results carry `source: "muse-spark-open" | "local"`, and each fallback is logged as `memory.fallback`. GP5 never dead-ends.

**Undo refusals.** `whyNot()` refuses an undo when:
- it was a send, judged by the tier recorded on the receipt or by the tool's current tier;
- the receipt is itself an undo;
- it was already undone;
- there's no undo step;
- the undo step's tool isn't registered;
- the undo step would run a send-tier tool. Undo steps skip the tap, so this rule enforces "undo steps are writes" instead of trusting it.

A refusal returns `{ok: false, message}` and writes nothing. When matching a description, sends stay in the running, so "undo the Slack post" is refused rather than undoing something else.

**Shared files (small, additive).**
- `tools/types.ts`: a new `ToolSpec.ownReceipt` flag. `receipts.undo` sets it because `undoReceipt` already writes the "Undid: …" receipt with `undoes`. Without the flag, the loop would add a second receipt, and the eval's `"receipts": 1` (GP5) and `2` (undo-a-draft) would be wrong.
- `agent/loop.ts`: the loop honours `ownReceipt`. `undoReceipt` now takes `Pick<AgentDeps, "log" | "tools" | "surfaces">`, and every existing caller still type-checks.
- `config.ts`: `basetenApiKey` (`BASETEN_API_KEY`), `basetenBaseUrl` (`BASETEN_BASE_URL`, default `https://inference.baseten.co/v1`) and `memoryModel` (`AUREN_MEMORY_MODEL`, default `meta-models/muse-spark-open-1026`).
- `index.ts`: one block after the tool registry. Spark Open is created only when the key is set, with `maxRetries: 1` and the shared ledger and ops log. `memory` and `receipts` are always registered.

## How to run it
```bash
cd core && node --test src/memory/memory.test.ts     # the 15 R8 tests, no keys
make test && make typecheck                         # everything
```
Live: add `BASETEN_API_KEY=` to `.env` (the line is already in `.env.example`), set `MODEL_API_KEY` for Muse Wonder, run `make dev`, then say or type "What did I get done today?" and "Undo the calendar move." Calls appear at `GET /v1/outbound` as Baseten.

## Verified (offline, against fakes)
- **Recap content.** After a scripted GP1, the Spark Open request has three receipts with times, apps and wrapped summaries, the Slack one marked `sent`, and no ids, arguments or undo steps. The card goes to the phone.
- **Ledger and ops log.** One Baseten row with the right operation, an `ok` status and its byte count. The `memory.call` ops line has the trace id and none of the contents.
- **Fallback** for four cases: no key (nothing leaves, and the ledger stays empty), a 503 error, a timeout (the hung request is aborted after 30 ms in the test) and an empty answer. Each still lists all three receipts.
- **Empty day.** "Nothing done on …", with no model call.
- **Recall.** Only keyword matches are sent: the draft to Prof. Lee is in, the calendar move isn't. With no matches, nothing is sent. When Spark fails, the local answer lists the matches.
- **Undo by description.** "the calendar move" puts office hours back at 3:00, with exactly one new receipt marked `undoes`. A second try is refused, and the recap marks the move `undone` instead of adding a fourth item.
- **Refusals.** A Slack post is refused by description and by id, the post stays and no receipt is written. Also refused: a receipt with no undo step, an undo of an undo, a double undo and an unknown id.
- **Through the agent loop with scripted Muse.** GP5's recap then undo writes 1 receipt, as `gp5-recap-then-undo` expects. `undo-a-draft` ("undo that") deletes the draft and leaves 2 receipts. Both namespaces are in the inventory, and the loop wraps the recap as untrusted data.
- The eval cases' `memory.recap` and `receipts.undo` exist with tiers read and write. `core/src/eval/cases.test.ts` still passes unchanged.
